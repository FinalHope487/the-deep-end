# 程序：向 user 提問、QUESTIONS.md

觸發：要問 user；執行中碰到要問的事；user 答了 `QUESTIONS.md` 的題。
讀者：agent。

## 要問 user 時

- 用 AskUserQuestion 一次問完整批
- 向 user 提問、回報或寫 `QUESTIONS.md` 時，凡提及規則、條目、計畫項目或檔案段落，直接寫出它的內容與全部下位條目，並寫出直接引用、依賴或衝突條目的內容；關聯先展開一層，不足以理解選擇則續展開，去重。不可只寫編號、節名或摘要：user 沒有 agent 讀過的上下文。user 要求時才附編號
- 首次出現非日常通用或專案自訂縮寫時，寫出完整名稱與意思；原文未定義全稱就說明意思，不猜測
- 每個待選或代 user 選的選項須交代客觀影響（改變／不變事項、限制、風險、成本、回退代價及未知），以及推薦理由；條目解釋不能取代影響說明
- 每個選項附「這樣選會怎樣」，標出推薦及理由，推薦照 `AGENTS.md`〈代 user 決策〉的偏好選
- 矛盾或會壞的：指出在哪（附 `檔案:行號`）與照字面做的後果
- 講清楚代價：不問直接做最壞會怎樣、事後改回來多貴
- user 重申或堅持原本的要求：照做，不再勸第二次
- user 的說法預設是意圖的例子，不是實作規格。先複述原則請 user 確認，要動手時才提做法

## 執行中才碰到要問的事

判準：這件事的正確做法會不會因未決問題而改變。不會就去做。

1. 寫進 `QUESTIONS.md`；環境有推播工具時發推播給 user
2. 受影響的部分留 stub，標 `BLOCKED(Q<編號>)`
3. 不對未拍板的外部契約做猜想式實作。待決部分停止推進，僅實作並驗證不依賴該決策的 Functional Core 純邏輯；若有已寫好但缺環境的測試，用條件式 skip 包住並在 `ROADMAP.md`〈待辦項目〉記一行
4. 換做不依賴答案的工作，其餘全部做完；再也找不到不受阻的工作時才停，一次端上全部

不得什麼都沒做就回報「這是高風險」。同一個決策點只寫一題；既有的題又擋住新工作時，在那題底下補一行現況。

## `QUESTIONS.md` 的題

一題＝user 看一次、答一次就結案。只寫這兩行，不寫選項：

    ## Q<編號> · <一句話問題>

    **為什麼有這題**：<哪個檔、哪個決策、哪個矛盾逼出這個問題>
    **沒答會怎樣**：<擋住哪件工作；已先照某個方向出貨就寫回退成本>

| 不是題 | 去哪 |
|---|---|
| 要 user 先看影片、跑程式、做完別的事才答得出來 | `ROADMAP.md`〈待辦項目〉 |
| 要來回好幾輪才收斂 | 拆成各自一次答完的題；拆不開就先做做得了的部分 |
| 驗證數字、收斂條件、使用說明 | commit message 或對應的說明檔 |

user 答完：刪掉原題，不得改寫成「已解決」留著，不留選項表與量測。內容搬走：

| 答案的性質 | 搬到 |
|---|---|
| 往後都適用的決策 | `DECISIONS.md` 加一行；會改變現行做法的同時改 `STATE.md` |
| 會重複出現的症狀與查法 | `SOP/` 對應的檔，附日期 |
| 這一輪之後要做的事 | `ROADMAP.md`〈待辦項目〉 |

答得不清楚：一樣刪掉原題，把還混淆的那一點寫成新的一題；不在舊題底下追問，不貼 user 原話。
